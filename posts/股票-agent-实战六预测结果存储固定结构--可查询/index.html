前言

第五课的多 Agent 已经能给出带 verdict（看多/看空/中性）的预测了。但预测不存下来，就是一次性结论：过几天想复盘「当时为什么看多」，只能翻聊天记录；想统计「我到底准不准」，没有数据。

这一课加一块地基：预测结果库——把每次预测按固定结构存起来，可积累、可查询、可审计，将来还能对照后续行情做回测验证。

一、什么是「固定结构」

固定结构 = 一份字段契约。每条预测必须长这样：

字段 类型 约束
id 整数 自增主键
created_at 文本 写入时间（UTC ISO）
symbol 文本 6 位股票代码
question 文本 触发本次预测的问题
verdict 文本 枚举：看多 / 看空 / 中性
confidence 文本 枚举：高 / 中 / 低
summary 文本 结论摘要
sections JSON 数组 分点结论
key_figures / risk_flags JSON 数组 关键数据 / 风险点（可空）
schema_version 整数 结构版本，为演进留后路

为什么固定：可消费（下游程序直接读）、可审计（每个结论有出处）、可回测（把 verdict 和后续行情对照）。

二、为什么选 SQLite

  • 零依赖：Python 内置，不用装数据库；
  • Schema 即契约：表结构强制字段存在，乱写不进去；
  • 事务与索引：写入原子，按 (symbol, created_at) 建索引查询快；
  • 单文件：predictions.db 一个文件就是整个库，方便备份。

数组字段（sections 等）SQLite 没有原生类型，用 JSON 文本列存，读写时自动序列化/反序列化。schema_version 字段保证将来加字段走迁移，而不是原地改表把老数据弄坏。

三、实现：schema + 写入 + 查询

SCHEMA_SQL = """
CREATE TABLE IF NOT EXISTS predictions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    schema_version INTEGER NOT NULL DEFAULT 1,
    created_at TEXT NOT NULL,
    symbol TEXT NOT NULL,
    question TEXT NOT NULL,
    verdict TEXT NOT NULL,
    confidence TEXT NOT NULL,
    summary TEXT NOT NULL,
    sections TEXT NOT NULL,
    key_figures TEXT,
    risk_flags TEXT,
    source TEXT NOT NULL DEFAULT 'stock-agent'
);
CREATE INDEX IF NOT EXISTS idx_predictions_symbol_time
    ON predictions (symbol, created_at);
"""

四、接入多 Agent

第五课的 REPORT_SCHEMA 增加 symbol 和 verdict 两个必填字段，首席分析师汇总时一并输出；team.py 加 --store 参数，结果直接入库：

五、运行与验证

# 预测入库
conda activate stock-agent   # 每次开新终端先切换环境
python stock-agent/team.py --store stock-agent/predictions.db "贵州茅台最近怎么样？"

# 查询（默认最近 20 条；--symbol 过滤；--json 输出原始结构）
python stock-agent/predictions.py --symbol 600519 --json

离线测试从 23 项增至 28 项（新增：写入/查询往返、按股票过滤、非法 verdict/confidence/sections 全部 fail fast）。预测库文件 predictions.db 已加入忽略规则，不入版本库。

六、小结

第六课的收获：

  1. 预测不留痕等于没预测——固定结构存储让结论可积累、可审计；
  2. Schema 是契约，不是摆设——枚举校验 fail fast，脏数据进不了库；
  3. SQLite 是最合适的起点——零依赖、单文件、可查询，够了再考虑上服务；
  4. 这层地基直接服务下一步——存下来的 verdict 可以对照后续行情做预测回测：看多/看空到底准不准。
