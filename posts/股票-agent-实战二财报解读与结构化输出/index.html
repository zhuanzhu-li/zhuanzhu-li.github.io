前言

第一课给 agent 装上了「行情」器官，能查到真实盘口和 K 线。这一课装第二个器官：财报。同时解决一个新问题：第一课的答案是自由文本，人看着舒服，但程序没法直接消费——「分析一下贵州茅台」和「自动生成持仓周报」之间，差的正是结构化输出。

一、场景：让 agent 解读财报

目标：问「分析一下贵州茅台最近的财报」，agent 调财报工具取真实数据，然后给出一份格式固定、字段可解析的分析结论。

自由文本回答的问题：

  • 不可程序消费：后续要做持仓周报、告警通知，都得解析自然语言，脆弱；
  • 不可评测：harness 第 7 课讲过，eval 需要「回答命中期望」的稳定格式；
  • 不可靠：同一问题两次回答结构不一样，前端没法渲染。

二、数据源选型：同花顺财务摘要

候选接口实测对比：

接口 特点 结论
stock_financial_abstract_ths（同花顺） 按报告期返回季度/年度，关键指标齐全：营收、净利、同比、EPS、毛利率、ROE、资产负债率等 ✅ 选用
stock_financial_analysis_indicator（新浪） 指标最细（60+ 字段），但只有年报、字段偏旧 ⏸ 留作扩展

工具只保留对分析最关键的 13 个字段，避免把模型撑晕：

报告期 / 营业总收入 / 营业总收入同比增长率 / 净利润 / 净利润同比增长率 /
扣非净利润 / 基本每股收益 / 每股净资产 / 每股经营现金流 /
销售毛利率 / 销售净利率 / 净资产收益率 / 资产负债率

三、实现：get_financial_summary 工具

与第一课完全同构：数据源层加一个函数，工具层包一层：

@tool(
    name="get_financial_summary",
    description="获取 A 股个股最近 N 个报告期的财务摘要：营业收入、净利润及同比增速、"
                "扣非净利润、基本每股收益、每股经营现金流、毛利率、净利率、"
                "净资产收益率(ROE)、资产负债率等，用于基本面与财报分析。",
    parameters={
        "type": "object",
        "properties": {
            "symbol": {"type": "string", "description": "6 位 A 股股票代码，例如 '600519' 是贵州茅台"},
            "periods": {"type": "integer", "description": "最近 N 个报告期，默认 4，最多 8"}
        },
        "required": ["symbol"],
    },
)
def get_financial_summary(symbol: str, periods: int = 4) -> list[dict]:
    return data_source.financial_summary(symbol, periods)

四、结构化输出：OutputSchema + chat_json

这就是 harness 第 4 课 OutputSchema / chat_json 的实战用法。思路是两阶段：

  1. 第一阶段：agent 自由调研，用工具把真实财报数据收进对话；
  2. 第二阶段：把整段对话交给 chat_json，强制模型只输出符合 Schema 的 JSON，不合规就带着错误信息重试。
ANALYSIS_SCHEMA = OutputSchema(
    fields={
        "summary": as_str,       # 一句话结论
        "key_figures": as_list,  # 关键数据点数组
        "risk_flags": as_list,   # 风险点数组
        "verdict": as_str,       # 看多 / 看空 / 中性
    },
    required=["summary", "key_figures", "risk_flags", "verdict"],
)

# 第二阶段：结构化结论
convo = agent.session.to_messages()
convo.append({"role": "user", "content": analysis_prompt(question)})
result = chat_json(agent.client, convo, ANALYSIS_SCHEMA)

verdict 只允许三个固定取值，key_figures / risk_flags 必须是数组——这些约束让输出天生可渲染、可入库、可评测。

五、运行与验证

conda activate stock-agent   # 每次开新终端先切换环境
python stock-agent/analyze.py "分析一下贵州茅台最近的财报"

六、小结

第二课的收获：

  1. 财报也是工具——数据源选型要看「返回节奏」和「字段完整度」，同构地加进工具层；
  2. 结构化输出让 agent 可消费——OutputSchema 把自由文本变成固定 JSON，为后续盯盘告警、持仓周报铺路；
  3. 两阶段模式——先自由调研取数，再强制结构化总结，比一步到位稳定得多。

下一步：盯盘提醒——按涨跌幅/价格条件触发通知，把 agent 从「问答」推进到「主动」。
