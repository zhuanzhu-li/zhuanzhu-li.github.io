前言

第六课把预测存进了固定结构的预测库。存了不看，等于白存。这一课把它画出来：每天一条预测，旁边就是次一交易日的实际涨跌，一眼看出「看多对不对、看空准不准」。

按你的要求，不引任何图表框架：纯标准库生成一个自包含 HTML，图表用手写 SVG 柱状图。

一、先定义「对错」的口径

没有口径就没有准确率：

  • 预测日 D：预测记录落库的日期（UTC 转北京时间按天归组）；
  • 实际结果：D 之后第一个交易日的收盘相对 D（或 D 当日）收盘的涨跌幅；
  • 判定：看多 → 次日涨为对；看空 → 次日跌为对；中性 → 不计入方向准确率；
  • 待验证：还没有后续交易日数据的预测（比如今天刚下的），单独标记。

这些判定逻辑全部是纯函数（compute_outcomes），离线测试覆盖：看多对、看空对、中性不计、无后续数据标待验证、准确率汇总。

二、又踩一个数据源的坑：日 K 也得上双通道

画图需要真实日 K。第一版用 AkShare 的 stock_zh_a_hist，被服务器反复断开；改成直连东方财富 K 线接口（带 UA）后仍然断——这次不是 UA 问题，是 push2his.eastmoney.com 这个域名当前从本网络根本连不通（盘口域名却正常）。

解法还是老配方：双通道。东方财富主、腾讯备（web.ifzq.gtimg.cn 实测正常），主通道挂了自动降级，工具层和报告层无感：

def _fetch_daily_http(symbol, days):
    try:
        return _fetch_daily_em(symbol, days)        # 主：东方财富
    except Exception:
        return _fetch_daily_tencent(symbol, days)   # 备：腾讯

数据源层第三次证明自己的价值：库坏、断连、域名被掐，上层一行都不用改。

三、手写 SVG，不引框架

报告是一个自包含 HTML：内联 CSS + 手写 SVG。每根柱子 = 一个预测日：

  • 颜色 = 预测方向（绿=看多，红=看空，灰=中性）；
  • 高度 = 实际次日涨跌幅（0 轴上下）；
  • 柱顶标注 = 实际涨跌% + ✓/✗（对/错）；
  • 待验证的预测画灰色小横条；

四、运行与验证

python stock-agent/report.py --days 60

五、小结

第七课的收获：

  1. 可视化之前先定口径——「对错」的定义决定准确率有没有意义；
  2. 无框架也能做出有用的图——手写 SVG 柱状图足够呈现按天对比，且零依赖、单文件；
  3. 数据源要双通道——域名级断连不是重试能救的，降级通道是标配；
  4. 预测库开始产生价值——准确率第一次变成数字，后面可以按符号、按置信度、按时间窗口拆开看。
