前言

ai-harness 系列从零搭了一个完整的 agent 运行时：模型封装、会话、工具循环、结构化输出、沙箱、可观测、评测。但那个 harness 是个空壳——它没有任何真实能力。

这个新系列要做的，是给空壳装上真实能力：一个 A 股股票 agent，从个股问答出发，逐步扩展到分析助手、盯盘提醒、财报解读、舆情监控。每篇仍然像 harness 系列一样，一篇文章加一个功能，每个功能背后是一个真实的工程问题。

配套代码在 ai-harness-tutorial 仓库的 stock-agent/ 目录，直接复用仓库根目录的 harness 包，不重复造轮子。

一、场景：让 agent 回答「贵州茅台现在什么价位」

目标很简单：用户问一句「贵州茅台现在什么价位」，agent 查到真实行情并回答。

最朴素的做法，是把 AkShare 直接暴露给模型：

import akshare as ak
df = ak.stock_bid_ask_em(symbol="600519")

能跑。但把这样的数据接口直接塞给模型，有三个问题：

  • 接口名是黑话：stock_bid_ask_em 是什么？模型只能靠猜；
  • 返回结构不稳定：接口返回中文列名的表格，字段含义模型不知道，接口还经常改版，改一次 agent 就瞎一次；
  • 没有参数约束：模型可能传一个不存在的代码、问一个接口不支持的参数。

二、工程化演进：数据源层 + 工具层

解决方案在 harness 第 3 课就写过：把函数包装成 Tool——名字、说明书（description）、参数 Schema、执行函数。今天只是换一批函数。

@tool(
    name="get_realtime_quote",
    description="获取 A 股个股的实时盘口行情，包括最新价、涨跌幅、成交量、量比、五档买卖等。",
    parameters={
        "type": "object",
        "properties": {
            "symbol": {
                "type": "string",
                "description": "6 位 A 股股票代码，例如 '600519' 是贵州茅台",
            }
        },
        "required": ["symbol"],
    },
)
def get_realtime_quote(symbol: str) -> dict:
    return data_source.realtime_quote(symbol)

注意 description 里写了「600519 是贵州茅台」——这是模型把「贵州茅台」翻译成代码的唯一依据。说明书质量，直接决定 agent 智商。

第一课只做两个工具：

工具 作用
get_realtime_quote(symbol) 实时盘口：最新价、涨跌幅、量比、五档等
get_daily_history(symbol, days) 近 N 个交易日日 K（前复权），用于分析走势

工具之下还有一层数据源层（stock/data_source.py），它比「调个接口」多做了两件事：

  • 缓存：agent 的工具循环可能在几秒内反复查同一只股票，TTL 缓存 10 秒，避免把数据源打到限流；
  • 归一化：把原始接口的中文列名、混杂类型统一成稳定的 JSON，模型读起来不晕。

以后想换 tushare、换券商接口，只改数据源层，工具和 agent 都不用动——这就是分层。

三、真实踩坑：UA 断连与接口抖动

写代码永远比预想的多两个坑。第一版用 AkShare 的盘口接口，真实运行时直接被行情服务器断开连接：

RemoteDisconnected: Remote end closed connection without response

排查发现：stock_bid_ask_em 的请求不带浏览器标识（UA），部分网络环境下会被东方财富服务器直接掐断。修复方式是数据源层直连东方财富 HTTP 接口并带上浏览器 UA。

然后第二个坑来了：带 UA 之后接口依然偶发抖动——一会儿 ProxyError，一会儿连接重置。实测 4 次里有 1 次失败。于是再加两道保险：

  1. 重试：主通道失败时指数退避重试 3 次；
  2. 降级：主通道彻底失败时，自动切到腾讯行情接口兜底。
def _fetch_realtime(symbol: str) -> dict:
    try:
        return _fetch_realtime_em(symbol)        # 主通道：东方财富
    except RuntimeError:
        return _fetch_realtime_tencent(symbol)   # 备用通道：腾讯

这两个坑正好说明「数据源层」为什么值得单独存在：数据源不稳定是常态，agent 的可靠性必须从数据源层开始加固。

四、运行与验证

用 conda 建项目同名环境（不污染全局环境）：

conda create -n stock-agent python=3.12 -y   # 首次创建环境
conda activate stock-agent                    # 切换 conda 环境
pip install -r stock-agent/requirements.txt
# 复制 stock-agent/.env.example 为 stock-agent/.env，填入 DEEPSEEK_API_KEY

# 真实模式（联网，走 DeepSeek + 东方财富/腾讯行情）
python stock-agent/main.py "贵州茅台现在什么价位"

# 离线模式（FakeLLM，不联网不花钱，验证整条链路）
python stock-agent/main.py --fake "贵州茅台现在什么价位"

# 离线测试
python -m unittest discover -s stock-agent/tests -v

真实问答输出示例：

贵州茅台（600519）当前行情如下：

- 最新价：1346.01 元
- 涨跌幅：-0.21%（跌 2.85 元）
- 今开：1348.00 元，最高 / 最低：1352.65 / 1338.18 元
- 成交额：约 12.23 亿元，换手率 0.07%，量比 1.15

今日小幅低开后窄幅震荡，整体波动不大。

离线测试覆盖四类行为：盘口归一化、K 线结构、工具 Schema、缓存命中；外加一个「主通道挂了自动降级」的用例。

五、小结

第一课的收获：

  1. 模型看不见数据，只看得见工具——给 agent 的是带说明书的函数，不是数据源；
  2. 数据源层独立存在——缓存、归一化、重试、降级都在这一层，换实现不动上层；
  3. 真实数据源会抖——UA 断连、连接重置都是生产常态，重试 + 双通道降级是标配；
  4. 错误要变成模型能读的文本——工具出错返回错误信息而不是抛异常，agent 才能自我修正（harness 第 3 课的设计在这里被真实场景验证了）。
